# 单智能体与多智能体配对评价协议

本实验评价当前实现的系统表现，不预设多智能体获胜，也不把一次小样本实验解释为理论上限。
生产Agent代码不因本轮成绩修改。原v1评测记录不覆盖。

## 设计

- 12类问题：3个单查询、5个复合分析、2段多轮、2个需要澄清的问题。
- 两个独立随机种子的数据实例，结构相同、记录不同；共24组配对，每组single/multi各执行一次，共48次。
- 数据实例不是新Schema。两份记录可降低单个数据集碰巧等价的风险，但不是跨Schema实验。
- 同一案例的两种模式相邻执行，并在第二份数据上反转先后顺序；不用历史成绩充当对照。
- 相同模型、温度、检索/重排、数据库、Schema、Skill和评分规则。
- Schema向量与重排模型预热；问题向量不使用跨条件缓存，避免第二个条件免费命中缓存。
- 正式轮单次网络超时90秒、外层最多1次尝试；每案例相同240秒墙钟上限。父进程可终止超时worker，防止长连接导致无限等待。
- 每次执行拥有独立graph、会话、偏好和固定业务时钟；多轮使用同一案例会话。
- 保持系统原本调用策略：多智能体最多3个任务、一次审核返工。它有更多自然调用预算，报告真实资源差异，不声称等Token预算实验。
- 非并发执行，避免CPU和模型服务竞争影响单次延迟。worker重启预热单列，不计为正常查询时间。

## 评分

主指标仅在有明确答案的问题上计算：

1. 完整事实覆盖率：全部参考结果是否在最终可用证据中出现。
2. 事实覆盖率：每案例正确事实数/所需事实数，按案例宏平均；多任务部分完成也有分数。
3. 严格完成率：事实完整且系统业务状态success。它与“已有足够正确数据”分开列出。

single可在一条SQL中使用JSON或带结果类型标签的UNION输出，不强制它返回multi专有的多个表协议。
评分器接受独立表、结构化JSON以及带明确标签的分区联合表，不任意从一大张错误结果中挑选有利行。
补充统一归一化：允许多个完全正确的子表合成同一参考结果（例如9月、10月各一表），
但子表不能含参考集合之外的额外行；该规则对两种模式同时应用。运行时原始分数保留，最终按统一重评分版本报告。
忽略列别名/列顺序与无语义的行顺序，保留重复行；数值沿用6位小数标准。
结果表示审计补充（统一重评分v3）：接受可无冲突透视的“指标名/指标值”长表。
金额和人均金额规范为2位小数，C2的退款比例规范为4位小数，计数严格整数。
该调整是因为原规则将展示性舍入和长表格式误判为业务错误；对单双模式全量同样处理，
保留predictions.jsonl中的原始六位规则分数和最终scorer hash，不修改被测Agent或参考SQL。
截断结果不采信。multi未审核通过的数据不作为最终证据；历史SQL可另作诊断，但不计为交付成功。

澄清题单独报告，不能靠它们提升主事实正确率：

- multi可用结构化clarification状态；single也允许用自然语言提出澄清。
- 初步自动规则识别“请求目标/指标/时间口径”等文本，仅为启发式。
- 提示信息SQL、既给武断答案又询问条件、无关报错等需人工复核；该分数不等于经过独立专家标注的澄清质量。

审核诊断统计实际review调用、返工、未通过任务，以及历史SQL中存在但最终证据未保留的参考事实。
它们是行为代理，不能直接当作审核precision/recall：中间子任务可能正确但不直接等于最终问题答案。

不使用同一个模型给自己打最终正确性分数。参考SQL在独立只读DuckDB中执行；标准答案不提供给Agent。
文字解释中的因果、引用和数字对应关系未全面自动评分，因此“结构化事实正确”不等同于完整自然语言回答正确。

## 统计与费用

- 分组报告单查询、复合分析、多轮，不用一个总分掩盖差异。
- 报告配对胜/负/平、延迟、已知LLM Token、Embedding、调用及重试数量、硬超时和服务故障。
- 超时保留意向分析：判未完成，未交付事实记0；终止时未返回用量标为未知。
- 同时列可观测到的故障数量；不静默丢弃失败并重跑取最好成绩。
- 如给出区间，按题目族聚类重采样，两个数据实例不假装成24个完全独立意图。
- 只有一次配置、每数据实例一次执行，不能据此确定理论上限或稳定的统计显著性。
- 不核实账户计费单价时只报已知Token，不伪造货币费用。

## 复现

在backend目录运行（真实API会产生费用）：

```powershell
python -X utf8 -m evaluation.comparison_data
python -X utf8 -m unittest test.test_comparison -v
python -X utf8 -m evaluation.comparison --name paired-main --deadline 240 --api-timeout 90 --api-attempts 1
```

同一name支持断点续跑，但代码、模型、数据和配置不一致时拒绝合并。不要覆盖已有输入或运行目录。
源码/数据hash、原始响应、逐次调用记录和超时记录保存在runs/paired-main/。

预算校准轮paired-v1采用25秒、2次尝试、180秒案例上限，在复合题两种模式都频繁超时后中止。
校准原始记录保留，不与正式轮拼接，也不从多轮中挑选最好成绩。正式轮在启动前统一固定新预算。
